# Example workspace checkpoint

The Vite shell loads stock react-map-gl. Expo web uses the same browser components. Expo native loads the chosen bound native entry. All shells start with the Seattle basemap and own engine switching, token configuration and camera handoff. The [package guide](../packages/one-map-react/README.md) explains the public imports. The [pre-migration example record](https://github.com/RobJacobson/one-map-react/blob/618cf7c5bcb2a72d7d256c9aaebd0b894eadf986/docs/examples-workspace.md) preserves the earlier browser facade and its checks.

## Development setup

Run `bun install` at the repository root. `bun run dev:web` builds the library and shared example package, then watches both alongside the Vite app. `bun run dev:expo` does the same for Metro on port 8081. The apps consume the built shared example. Native entries resolve through the library’s package exports. Vite emits MapLibre's worker as a separate asset. Expo scripts copy the unchanged pinned worker into the ignored public directory before Metro starts or exports the website. Source aliases remain confined to the existing library and scenario type checks; the running apps use built workspace exports.

The default map uses Seattle at longitude -122.34, latitude 47.61, zoom 11, bearing 0, and pitch 0. MapLibre starts without credentials. Both engines use the same [OpenFreeMap Liberty style](https://tiles.openfreemap.org/styles/liberty), which supplies its attribution. The top controls select an engine. Camera state survives keyed renderer replacement; callbacks from a retired map cannot update the replacement. Readiness requires public camera readback to match the requested camera, rather than command acknowledgement alone. Mapbox Native retains bearing and pitch from normalized movement events because its public getters are unavailable.

Set a public `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` in the shell or root `.env.local`/`.env`. The existing `MAPBOX_ACCESS_TOKEN` setting is also accepted when the new setting is absent. An explicit empty new setting disables Mapbox. Secret tokens are rejected before configuration enters a client bundle. Restart the development command after changing configuration.

The Vite development URL accepts `?test=1` to show the basemap readback panel. Open its scenario selector, or use `?engine=maplibre&scenario=tf04` directly. Expo web accepts the same explicit engine and scenario query. Both browser apps use [the shared selection parser](../packages/example-map/src/acceptance-selection.ts) and reject unknown selections before creating a renderer. Existing runner queries, such as `?tf04=1&engine=maplibre`, remain supported. Production exports exclude these development controls.

For native development, set `EXPO_PUBLIC_ONE_MAP_TEST_MODE=1` before starting Metro to expose the basemap panel and its Acceptance scenarios button. Set `EXPO_PUBLIC_ONE_MAP_SCENARIO=tf04` and `EXPO_PUBLIC_ONE_MAP_ENGINE=maplibre` to open a scenario directly. The native controls select one engine and scenario tree at a time. Replacing that tree retires its callbacks and camera observer. Mapbox selection requires a public token; ordinary startup stays on the basemap.

Expo uses SDK 57.0.23, React Native 0.86.3, and React 19.2.3. Expo CLI 57.0.25 is pinned to avoid a newer transitive dependency blocked by the existing release-age policy. The build-properties plugin enables the SDK 57 scene lifecycle required by the installed Xcode 27 and iOS 27 SDK. The library's declared React Native peer range remains unchanged; the private Expo dependency tuple does not widen it. Passing routine JavaScript checks does not renew renderer acceptance.

The native app includes RNMapbox 10.3.19 and MapLibre React Native 11.5.1. Root Bun configuration applies exact-version patches. The RNMapbox patch gives its generated map-view module a distinct namespace so both native wrappers can link in one application; registry names remain unchanged. Expo configuration pins the Mapbox Maps SDK to 11.33.0 on both platforms and MapLibre Native to iOS 6.31.0 and Android 13.6.1. Both plugins are configured together. Native projects are generated from configuration and ignored by Git. No native generation, compilation, installation, or execution belongs to the routine checks below.

## Acceptance execution boundary

The [workspace launcher](../scripts/workspace-smoke-shell.mjs) selects Vite by default. Set `ONE_MAP_WEB_SHELL=expo` to run the same browser scenario through Expo web. The family runners keep their platform and engine arguments. The lifecycle runner takes a platform and engine; the extended browser UI runner takes an engine. Workers receive isolated application ports, fixture ports, browser profiles, caches, and fresh output directories. Native runs share one exclusive worker and remain sequential.

Native runners start Metro and open an already installed Expo development client. They do not build or install it implicitly. Preparation generates native projects from Expo configuration, builds both SDKs into the same application, installs that application, and records its identity. `ONE_MAP_ACCEPTANCE_APP_ID` must identify a separate `org.onemap.acceptance.*` test application. `ONE_MAP_NATIVE_BINARY_SHA256` pins the installed APK or iOS debug image. Assign `ANDROID_SERIAL` or a dedicated iOS simulator explicitly. After verifying the installed image, the iOS launcher disables Expo's floating tools button through a process launch preference so it cannot intercept scenario controls. Individual suites retain their additional binary, library, peer, and manual-observation checks; those checks must match the same prepared application.
