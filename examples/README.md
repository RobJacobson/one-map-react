# Shared map examples

**Working Images migration.** The [named style image contract](../docs/sources-and-layers.md#named-style-images) retains a small web polyfill because react-map-gl has no Images component, while native adapters delegate to their wrappers. Web applications must finish Images unmount cleanup before any style replacement, then mount fresh Images after readiness; changing only an Images key after onStyleLoad is insufficient. A new keyed Map with reuse disabled is an alternative boundary. Automatic web replay/retry is excluded; native normal restoration is retained. Image replay/retry descriptions and acceptance outcomes below retain their historical artifact scope. They do not establish renderer acceptance for the changed lifetime.

**Working feature-click migration.** The [map-click migration](../docs/revised-api-proposal.md#rendering-and-queries-stay-shared) uses Map.onClick with interactiveLayerIds for source activation. Source.onClick, SourceClickEvent, synthetic source bubbling, selected facade native source hitbox additions and UserLocation.onPress are removed. Raw native Wrapper source onPress/hitbox facilities, source refs/queries/state, live markers/portals and supplied location geometry/accuracy remain. Native filtered clicks retain queries at the actual logical map point, observable errors and stale-map callback protection. The future native focused source stop/bubbling probe is retired; historical scenario IDs and outcomes remain attached to their recorded artifacts. Renderer/query/touch behavior, Metro and native builds/installations remain unverified.

Geolocation examples use raw selected web WrapperGeolocateControl and a native application button for one-shot acquisition and easeTo. Native screens own acquisition cancellation, stale-result suppression, teardown and errors through selected SDK facilities; they do not supply a replacement continuous-follow controller. Raw web controls follow the selected wrapper and browser geolocation rather than the native injected acquisition callback; the former common injected web-follow policy is retired. The browser driver uses browser permission and coordinate emulation; its common injected rejection/delay/result and streaming-follow assertions are retired. Native continuous follow, gesture-resume and coalescing assertions are also retired; historical acceptance IDs and outcomes remain unchanged. Library location services, useMapServices, MapServices, MapSetup.locationProvider, Adapter.services, service contexts/scoping and acquisition-only types/factories are removed. Applications own permissions, acquisition and cleanup through selected SDK or browser facilities. UserLocation is display-only; source activation uses Map.onClick with interactiveLayerIds. Native one-shot acquisition accepts selected manager cache replay; native permission prompts remain upstream and disposal suppresses their late results. Browser acquisition releases its owned watch on disposal. See [location migration guidance](../docs/revised-api-proposal.md#setup-and-location). Browser/sensor behavior and native button touches remain unverified.

Scale and attribution examples use raw selected web WrapperScaleControl/WrapperAttributionControl and native selected SDK ornaments. The native TF07 harness enables the selected scale and keeps SDK attribution/logo defaults; its former common units action is retired. The browser units action remains raw web control behavior. The native TF07 screens place the application location button at top: 8, left: 8, the SDK scale at top: 64, left: 8, and the compass at top: 148, right: 8 to clear the camera button group. Native TF08 uses top: 8, right: 8 for its location button and top: 64, right: 8 for the coverage-mode compass. SDK pixel placement still needs renderer verification. This changes the new harness scope without changing historical acceptance IDs or outcomes. No supplemental native legal text is added where the style/source attribution already supplies it. `shared/route-map.tsx` renders the TF02 map, GeoJSON source, and line layer. Each shell selects one adapter, sizes the map, and owns the remount and fly-to controls. Metro and Vite pin shared imports to that shell's `node_modules`. Mapbox shells read `MAPBOX_ACCESS_TOKEN` from the shell or a gitignored `.env` file. The shell variable wins. An example `.env` wins over the repository `.env`. Copy `.env.example` to `.env` and set the public token there, or export `MAPBOX_ACCESS_TOKEN` before starting Vite or Metro. Do not commit a token. The examples embed that public value in the local bundle, so a secret token must not be used. Restart Vite or Metro after changing it.

Web shells use Vite+ for development and production builds. From the repository root, `bun run build` writes the package `dist/` that the shells import. Then from `web-mapbox` or `web-maplibre`:

```sh
bun install
bun run dev
```

Native shells commit the JavaScript app, `app.json` registration name, Babel config, Metro config, and the React Native 0.87 `Gemfile`. From the repository root, `bun run build`, then generate `ios/` and `android/` with `bun scripts/setup-native-example.mjs`. Follow the example README for install and launch commands. Generating those directories shows that scaffolding runs; it does not show that the app builds.

Example installs and launches are not part of `validate`. Packed-consumer isolation is `bun run test:peers`.

`bun scripts/tf04-camera-smoke.mjs` is the TF04 renderer smoke. It is not part of `validate`. Web runs fit, click, stop, and a controlled jump. Android and iOS each start Metro on port 8081 with `ONE_MAP_SMOKE` set, then install with `--no-packager`. Android writes `debug_http_host` to this Mac's current LAN address before a cold start. MapLibre also waits for a double tap while pinch zoom is off. Android passes when that double tap does not zoom, because MapLibre Android requires zoom gestures. iOS passes when the double tap zooms. iOS posts the status line to the runner. The runner taps through an XCUITest driver, because Xcode 27 does not deliver SimulatorKit mouse events to the booted simulator. Pass `web`, `android`, or `ios` to run one group.

Independent native image observations use the [Mapbox snapshot module](shared/mapbox-snapshot.ts) or [MapLibre snapshot module](shared/maplibre-snapshot.ts), injected by their native application shells. Each calls its selected raw manager and adapts returned output for the application observer. Common snapshot normalization and deadlines are removed; actual native image execution remains unverified for the migration.
