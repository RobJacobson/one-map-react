# TF08 proposed implementation

**Proposed API and implementation plan.** TF08 should add foreground location services, explicit location display and following, persistent native offline packs, current-map capture, and independent native snapshots. Extend the existing facade and selected adapters, retain wrapper ownership, and keep device services independent of a mounted map. This proposal does not mark TF08 implemented or accepted.

The review covers first-party source at `2fcdddf`, RNMapbox 10.3.7, MapLibre React Native 11.5.0, react-map-gl 8.1.3, Mapbox GL JS 3.32.0, and MapLibre GL JS 6.13.0. Upstream observations below come from the installed sources at the [recorded baseline](../records/version-baseline.json). The [requirements](requirements.md), [stage plan](stage-plan.md), [coding guide](coding-style.md), and [testing policy](testing-policy.md) govern implementation. The older [capabilities research](capabilities-and-extensions.md) supplies inventory references; its retired `MapRef.extensions`, capability framework, and provider examples do not define the current implementation.

## Code review findings

1. **Extend the current geolocation control without breaking injection.** [The common contract](../packages/one-map-react/src/contracts/ui-types.ts) already defines `GeolocationPosition` with millisecond timestamps and `getCurrentPosition`, `zoom`, callbacks, and `trackUserLocation`. [The native control](../packages/one-map-react/src/adapters/shared/native-ui.tsx) requires injection and rejects tracking. [The web control](../packages/one-map-react/src/adapters/web/ui.tsx) delegates browser acquisition or composes an injected one-shot control. Preserve both existing one-shot paths while adding an explicit streaming provider.
2. **Add app-level services outside `MapRef`.** [Adapter](../packages/one-map-react/src/contracts/adapter.ts) currently contains components; [MapSetup](../packages/one-map-react/src/facade/map-setup.tsx) owns selection and map registration. Location acquisition, offline packs, and independent snapshots can operate without a map. Exposing those only through a map ref would create an artificial lifetime dependency. Current-map capture belongs on `MapRef` and its [deferred proxy](../packages/one-map-react/src/facade/map.tsx).
3. **Convert location values at each backend boundary.** [MapLibre iOS serialization][ml-location-value] emits seconds since the Unix epoch; [Android][ml-location-android] emits milliseconds. Multiply only the known iOS input by 1,000. Its `coords.heading` is iOS course, while RNMapbox distinguishes heading and course and documents an Android heading limitation in [its location type][rn-location]. Do not advertise a shared device-compass heading by renaming course.
4. **Separate permission outcomes from location results.** [RNMapbox's helper][rn-permission] accepts either Android permission; [MapLibre's manager][ml-location] requires both, so approximate-only access can produce a false denial. MapLibre catches acquisition errors and can return `undefined`; RNMapbox catches last-known-location errors and can return cached data or `null`. Neither result proves a fresh fix or permission denial. RNMapbox's public location manager supplies no equivalent iOS permission-query/request method.
5. **Respect singleton ownership.** Both location managers start when adding the first listener and stop when removing the last. Both offline managers hold one callback pair per pack. Cleanup must remove the facade's listener, and multiple facade subscribers need local fan-out. Calling global location `stop()` or `removeAllListeners()` during one component's cleanup can interrupt other users.
6. **Normalize persistent pack identity and creation timing.** [RNMapbox][rn-offline] returns `void` from creation and retrieves packs by name; [MapLibre][ml-offline] returns a pack with a generated ID. RNMapbox accepts northeast/southwest bounds, while MapLibre accepts flat west/south/east/north bounds. MapLibre attaches listeners after native creation and automatically removes them on completion; creation callbacks alone cannot establish terminal state.
7. **Define capture scope before exposing it.** [RNMapbox iOS][rn-map-ios] and [MapLibre iOS][ml-map-ios] draw the map view hierarchy. Their Android paths invoke SDK snapshots, while web exports the renderer canvas. These calls cannot establish identical marker, popup, ornament, or control inclusion. An independent snapshot also cannot reproduce facade-added sources or React children merely by reusing a camera and style URL.
8. **Provide browser capture configuration.** [The web map implementation](../packages/one-map-react/src/adapters/web/map.tsx) and selected map types do not currently expose drawing-buffer preservation. Mapbox uses `preserveDrawingBuffer`; MapLibre uses `canvasContextAttributes.preserveDrawingBuffer`. Add a deliberate construction option and account for retained maps and caller-owned WebGL contexts.
9. **Resolve two pinned snapshot defects.** [RNMapbox's snapshot options][rn-snapshot-options] use `options.zoomLevel || 16.0`, changing zero to sixteen. [MapLibre Android's static manager][ml-static-android] logs snapshot errors and releases its snapshotter without rejecting the promise; its null-output branch also leaves cleanup incomplete. A timeout can bound the caller's wait but cannot repair native resource ownership. Prefer narrow upstream patches or a verified wrapper release, with remove conditions and failure tests, before advertising those contracts.

## Proposed public boundaries

Add a small, typed `services` record to each `Adapter` with `location`, optional `offline`, and optional `staticMapImage`. Export `useMapServices()` from the common entry to read this record under `MapSetup`, including outside a mounted `Map`. Setup code can also use `adapter.services` directly. These three properties describe implemented services; an absent optional service means that contract is unavailable. Do not infer availability from platform strings or restore the retired generic extension dispatcher.

Allow an application-supplied `locationProvider` on `MapSetup` to replace the default acquisition/permission service. Treat this as a stable setup input; changing it requires a new setup key and disposal of the old setup's facade subscriptions. Preserve `GeolocateControl.getCurrentPosition` as the existing one-shot override. A new control-level `locationProvider` supports streaming overrides; supplying both control overrides is invalid. Resolve providers in order: control override, setup override, adapter default. Browser controls using the adapter default retain SDK delegation and its existing events; either explicit provider override selects the composed control. Selected-entry wrapper controls retain their complete upstream options and refs.

Keep portable contracts in new domain modules `location-types.ts`, `offline-types.ts`, and `capture-types.ts`. Extend `GeolocationPosition` in its existing owning module or move it once and re-export the same public name. Keep SDK types in selected entries. Add explicit common and selected exports, and verify optional-peer isolation and both mixed-engine selections. Missing TF08 implementation must remain distinguishable from a substantiated unavailable operation.

## Location acquisition and permissions

The proposed `LocationService` has `requestPermission()`, `getCurrentPosition(options)`, and `watchPosition(onPosition, onError, options)`. The watch returns an idempotent unsubscribe function immediately, including while permission/setup work is pending. `getCurrentPosition` resolves to an actual position or rejects; watch errors are operational events. Both calls need finite deadlines for initial acquisition. Start with `timeoutMs: 15000` and `maximumAgeMs: 0`; validate nonnegative finite values. Do not promise browser high-accuracy options on native managers that cannot honor them.

The native managers expose update listeners without an equivalent public error stream. Report observable permission/setup failures, invalid payloads, and acquisition deadlines, but do not promise immediate revocation or sensor-failure notification from those listeners. An application provider can supply stronger error reporting. Investigate supported wrapper extension paths before proposing a native bridge for any remaining required behavior.

Preserve `lngLat`, accuracy in meters, and optional millisecond timestamps. Add optional altitude, altitude accuracy, speed in meters per second, and course in degrees where the source establishes their meaning. Omit unknown measurements and documented invalid sentinels; a missing timestamp cannot establish that a cached fix satisfies a freshness limit. Keep device-heading data in named native facilities until its meaning is established per backend. Never substitute `[0, 0]`, the current map center, or a fabricated timestamp for a missing fix.

On native, use a temporary listener to obtain a fresh fix when cache age is unacceptable, remove it on success/failure/timeout, and suppress callbacks after disposal. Delegate actual manager start/stop to `addListener`/`removeListener`. Foreground watches release the facade's listener on backgrounding and restore it on return while still subscribed; a pending one-shot request rejects when foreground acquisition is interrupted. Keep this adaptation local where the wrapper does not already supply equivalent behavior. Browser acquisition uses `navigator.geolocation`, with `clearWatch` on disposal. Map-only mounting and common location display perform no acquisition. Wrapper-native pucks that activate acquisition keep that behavior explicit in their selected API documentation.

Use a permission result that distinguishes `granted`, `denied`, and `unknown`, with accuracy authorization reported separately as precise, approximate, or unknown. Acquisition accuracy radius is not proof of authorization precision. On Android, use React Native's public permission APIs to recognize coarse-only grants, preserving the raw request result when a blocked distinction is available. On MapLibre iOS, delegate its public foreground request and report accuracy authorization as unknown. Do not turn RNMapbox's `setRequestsAlwaysUse` into a permission request.

For RNMapbox iOS, require an application permission integration for an explicit request/result contract; without it, `requestPermission()` rejects with an actionable unavailable-operation error. Explicit acquisition may retain the wrapper/OS authorization behavior, documented separately. A successful fix establishes usable acquisition, not all authorization states. Browser permission inspection is optional where supported; requesting location can prompt, while mounting a service cannot. Neither a permission query nor an unavailable permission API should silently start a location watch.

Foreground use is the common contract. Named native manager facilities retain background/always-use configuration, displacement, event throttling, and simulation APIs with their platform semantics. App manifests, iOS usage descriptions, selected Android location engine, and application lifecycle requirements belong in setup documentation. Full background behavior and physical sensors require their own device evidence; a simulator result cannot establish them.

## Location display and following

Add `UserLocation` accepting a supplied `GeolocationPosition`, an accuracy-circle flag, and an optional press callback. Reuse `Source`/`Layer` for a renderer-drawn dot and meter-based accuracy geometry; generate stable per-instance source/layer IDs. This allows application locations and test fixtures to display without activating a device manager. Do not duplicate the native marker projection or portal infrastructure for this dot. Retain SDK puck imagery, pulsing, bearing, models, custom providers, and platform rendering options through typed selected exports such as `LocationPuck`, `CustomLocationProvider`, and `WrapperUserLocation`.

Native `GeolocateControl` should acquire only after activation. With tracking disabled it centers once and releases acquisition. With tracking enabled it owns one location subscription, displays updates, and follows their coordinates. Preserve the existing default centering zoom of fourteen. User gestures suspend following while location display continues; a second activation resumes following. Turning tracking off, unmounting the control, provider replacement, target-map detachment, or terminal acquisition failure releases its subscription and pending work. Transient watch errors retain the watch only when the provider documents recovery.

Use the existing map session's normalized movement events to distinguish user gestures from facade camera commands. Coalesce updates to the latest position while a camera dispatch is pending. This is local follow coordination, not a global camera queue. Suppress late results using attachment/request generations, including after application callbacks detach the map. The current native boolean activity guard is insufficient as the only protection when extending this path to subscriptions and replacement maps. Camera command resolution still acknowledges dispatch rather than completed movement.

Common following initially centers supplied positions and leaves bearing/pitch unchanged. Native heading/course follow and upstream mode-change events belong in selected `Map.locationOptions`, applied to the adapter's existing wrapper `Camera`. Do not mount a competing camera component. Reject conflicting portable follow, selected SDK follow, and authoritative `viewState` requests; do not let them alternately overwrite each other. Define interruption and resume behavior for selected SDK tracking from its actual events. Web default controls keep SDK tracking behavior; document differences from injected/native following and preserve the wrapper control for applications needing that exact behavior.

Equivalent acquisition and display intent can be traced without assuming identical wrappers:

- RNMapbox: register `locationManager.addListener(listener)`, normalize its payload, and later call `removeListener(listener)`; native puck display is a separate selected choice.
- MapLibre React Native: register `LocationManager.addListener(listener)`, normalize its payload and iOS timestamp, and later call `removeListener(listener)`; mounting its `UserLocation` also acquires through its hook.
- Web: use `navigator.geolocation.watchPosition(success, failure)` and `clearWatch(id)` for explicit acquisition; the default SDK control remains a delegated acquisition/display/follow composition.
- Proposed one-map-react: subscribe through `services.location.watchPosition`, pass each result to common `UserLocation`, and dispose the returned subscription; use `GeolocateControl` when a button should own the composition.

## Offline packs and tile stores

The proposed `OfflineService` exposes `createPack`, `getPack`, `getPacks`, `deletePack`, and `subscribe`. A pack handle provides identity, user metadata, bounds, `status`, `pause`, and `resume`. Creation requires a nonempty application ID, style URL, common southwest/northeast bounds, and explicit minimum/maximum zoom. It resolves when the pack is created and discoverable, not when download completes. A missing pack returns `undefined`; storage, authentication, and native failures reject. Pause/resume acknowledge the wrapper operation; completion requires status evidence.

After RNMapbox creation, call `getPack(id)` and reject if no pack is returned before constructing the common handle. MapLibre can use the returned pack directly. Normalize MapLibre's specific missing-pack outcome to `undefined` without converting unrelated lookup failures into absence.

Use the application ID as RNMapbox's name. For MapLibre, persist a versioned facade identity inside reserved metadata and reconstruct the application-ID/backend-ID mapping from `getPacks()` after restart. Keep user metadata under a separate field, reject duplicate IDs, and serialize same-ID creation within the facade service. Imported packs without facade identity remain discoverable under an explicit backend identity; never silently adopt or overwrite them. Duplicate persisted identities are a reconciliation error. No second database or map-instance registry is needed.

Convert common bounds to RNMapbox `[northeast, southwest]` and MapLibre `[west, south, east, north]`. Validate bounds using the common helpers, and give antimeridian regions a documented validated path or explicit rejection until both native contracts are established. Normalize status to `inactive`, `active`, `complete`, `invalid`, or `unknown`; preserve unavailable percentage/count fields instead of inventing zero. RNMapbox progress events and polled pack status use different declared state shapes. Decode each at its owning boundary using inspected native constants and payloads.

Install one upstream callback pair per facade-managed pack and fan out to local subscribers. Read status after creating or subscribing to catch completion before listener attachment. Both wrappers remove listeners on completion, so resuming/invalidating a pack must reattach the facade observer when subscribers remain. Async subscription establishment must check disposal again before retaining an observer. Unsubscribing releases observation only; it must never pause or delete the download. Failed creation releases partially attached callbacks and reports any pack that was created before a later failure, so callers can recover it.

Global cache controls, invalidation, merging regions, migration, quotas, tile-count limits, and progress throttling retain typed named methods in the native service or selected entry. Keep RNMapbox `tilesets`, `offlineManagerLegacy`, and `TileStore.shared(path).setOption(...)` discoverable with selected types. Verify legacy operations against the current v11 bridge before declaring them supported. Do not equate ambient cache with a downloaded pack, a tile-store quota with reservation, or deleting a pack with deleting shared resources. No automatic cache reset, migration, or database deletion occurs during service disposal.

For equivalent bounded native downloads, RNMapbox receives a name, `styleURL`, and reversed corner bounds; MapLibre receives `mapStyle`, flat bounds, and persisted logical identity metadata. Both proposed calls use `services.offline.createPack({ id, mapStyle, bounds, minZoom, maxZoom })`, with progress observed separately. Browser adapters expose no native pack service. Ordinary browser caching does not satisfy offline-pack completion, and a remote static-image service does not satisfy offline rendering.

## Current-map capture

Add `MapProps.captureEnabled`, default false and fixed for a map attachment, plus `MapRef.capture({ output, scope })`. `output` is `data-url` or native-only `file`; `scope` is explicitly `backend` or `renderer`. Return a discriminated result with output kind, PNG MIME type, URI, and scope. Normalize raw base64 and existing data URLs once, reject empty/invalid output, and reject file output on web. Temporary files remain OS-managed until the caller copies them; returning a file URI does not guarantee permanent storage or promise a deletion API the wrapper lacks.

`backend` means the selected wrapper's capture contents and is the proposed initial path in all six environments. Web excludes DOM markers and controls. iOS view captures can include native children and ornaments, but facade portal siblings need separate verification. Android SDK snapshots have their own inclusion behavior. `renderer` promises renderer content without host overlays and must reject on a path that cannot establish that scope. Prefer a supported public wrapper extension or upstream patch if strict iOS renderer capture is required; do not hide overlays temporarily or rebuild the visible map to imitate capture parity.

On web, translate `captureEnabled` into Mapbox's `preserveDrawingBuffer: true` or MapLibre's nested canvas context option during construction. Validate an external context with `getContextAttributes()` and reject incompatible capture requests. A retained map's context cannot be reconfigured: inspect actual context attributes on reuse and reject capture enablement when incompatible, with instructions to create a fresh map. Do not infer compatibility from the newly mounted props. Avoid enabling buffer preservation for every map.

Capture requires an attached map, nonzero dimensions, and an observed rendered frame. Wait for an applicable rendered frame with a bounded timeout; release listeners on success, error, timeout, and detachment. Resolve only when image output is available. Reject results from a replaced attachment. Preserve renderer/security/resource failures as failures, including canvas export restrictions; do not return a successful empty image. Capture does not promise pixel-identical outputs across SDKs.

Equivalent current-map calls are RNMapbox `map.takeSnap(false)`, MapLibre `map.createStaticMapImage({ output: "base64" })`, and web `map.getMap().getCanvas().toDataURL("image/png")` after capture-enabled construction and rendering. Proposed callers use `map.capture({ output: "data-url", scope: "backend" })`. This normalization changes output shape and lifecycle handling; it preserves the stated backend capture scope.

## Independent snapshots

The optional `services.staticMapImage.create(options)` operates without a mounted map. Require a style URL, positive dimensions, output kind, and either center/zoom/bearing/pitch or bounds. Reject ambiguous camera forms. Keep MapLibre style-object input and backend logo options in typed selected facilities until their semantics are shared. A static snapshot renders only the supplied style and camera; mounted sources, layers, UI, feature state, and location subscriptions are not inherited.

Forward to RNMapbox `snapshotManager.takeSnap` with field conversion, or MapLibre `StaticMapImageManager.createImage`. Browser adapters have no equivalent wrapper manager; keep this service absent until a distinct local offscreen-rendering design exists. A paid HTTP image service would require a separate explicit contract and is not a transparent fallback.

Define common dimensions as requested PNG pixels. Validate decoded output dimensions at two native densities before claiming exact sizing. The current native implementations differ: RNMapbox iOS fixes snapshot pixel ratio to one, RNMapbox Android derives a truncated display-density ratio, MapLibre Android supplies display density, and MapLibre iOS constructs a size without an explicit scale in the wrapper. Establish actual output sizing and adapt through public inputs where possible; use a targeted patch if exact dimensions cannot be honored. Keep native-unit behavior named and explicit until then.

Land or select a verified fix for RNMapbox zoom zero and MapLibre Android promise rejection/cleanup. Preserve native errors through the common result rather than translating a stalled request into unsupported functionality. Add a bounded facade deadline for defensive failure reporting, while documenting that it does not cancel an upstream snapshotter without a public cancellation facility. Never bypass wrapper internals with an undocumented native-module call to avoid these defects.

## Implementation order and affected files

1. **Freeze contracts and verify upstream defects.** Add source/unit reproductions for timestamp conversion, approximate-only permission, and snapshot zoom zero, and inspect the Android failure/cleanup path. Specify capture-inclusion, sizing, and native-failure probes for completed-checkpoint acceptance. Resolve required upstream patches/releases before marking affected behavior implemented. Use a short decision record for capture scope and permission integration; source review alone does not close runtime gates.
2. **Add service contracts and selection.** Extend `contracts/adapter.ts`, add domain types, update `facade/map-setup.tsx`, add `facade/map-services.ts`, and update `src/index.ts` and all four selected entry modules. Return stable service references; do not create managers on React render or read browser globals at module import. Verify common imports with no renderer peers.
3. **Implement location services and UI.** Add local `location.ts` per native adapter and a shared browser location service. Add a common display component, extend the existing UI factories and `GeolocateControlProps`, and apply selected native follow fields to the current camera in each `map.tsx`. Keep permission integration separate from value conversion and listener ownership.
4. **Implement persistent offline services.** Add `offline.ts` per native adapter. Share pure identity/bounds/status conversions only where equivalent. Use a small pack-observer owner for demonstrated callback fan-out and attachment cleanup. Add typed named native exports for tile-store and remaining offline facilities.
5. **Implement capture and independent images.** Extend `camera-types.ts`, `map-types.ts`, all three map-ref implementations, web wrapper contracts/construction, and the deferred-ref tests. Add native static-image services and one pure PNG-output normalizer. Keep map-bound frame listeners separate from app-level snapshot calls.
6. **Complete inventory and documentation.** Reconcile relevant entries in `records/api-coverage.json`, update stage/evidence summaries only for actual implementation and checks, and add setup/examples for permissions, restart persistence, files, output scope, and selected facilities. Update the existing capability and marker/control references so current behavior is separate from preserved research.

Historical inventory families S30–S37 contain 539 entries: S30 acquisition/permissions (52), S31 display (67), S32 follow (23), S33 web geolocation (165), S34 packs (134), S35 tile stores (6), S36 capture/canvas (18), and S37 independent images (74). These are checklist counts, including types, fields, and aliases, not implemented API counts. Review adjacent `UserLocation`/hook/camera/constructor exports as well: historical stage labels are not a complete TF08 filter. Some S36 canvas entries concern canvas sources and belong to TF09; record that ownership instead of claiming capture covers them. Every applicable entry needs a common mapping, named API, or substantiated disposition; raw SDK access alone cannot close it.

## Verification and completion

Routine checks should cover conversion inputs and units; fresh versus cached fixes; null/undefined acquisition; permission denial and approximate access; watch disposal during async setup; Strict Mode; provider/map replacement; callback-triggered unmount; multiple location subscribers; gesture interruption; follow conflicts; persisted IDs after restart; duplicate creation; listener fan-out; completion before subscription; reattachment after resume; partial create failures; file/data-URL normalization; detach during capture; context reuse; snapshot zero zoom; and failure propagation. Group unchanged forwarding checks and avoid a test for every inventoried field.

Run formatting, documentation structure/links, relevant type configurations, focused mocked suites, build, packed consumers, peer isolation, and example resolution. Inspect aggregate commands first. This proposal changes documentation only, so its immediate checks are documentation validation and diff review; it does not need renderer execution or production-code tests.

After implementation, review, routine checks, and patch integration finish, prepare separate acceptance scopes:

- **Browser Mapbox and MapLibre:** user-triggered success/denial, deterministic injected tracking, gesture interruption/resume, actual canvas capture, overlay inclusion, retained-context compatibility, external-context rejection, and export failure. Use local styles and independent image-content assertions.
- **Both native backends on iOS and Android:** injected acquisition/follow/display, detach/cleanup, offline creation/progress/pause/resume, completed resources surviving application restart, known-region rendering with networking disabled, capture inclusion, independent images, zoom zero, two output densities, and invalid style/resource failures that settle their promises. Keep service-backed downloads bounded and separate from local fixture checks.
- **Physical iOS and Android devices where claims depend on them:** real permission denial/revocation, approximate authorization, fresh position acquisition, compass/course meaning, and foreground/background transitions. Record unsupported or untested hardware/backend combinations explicitly. Emulator injection proves translation and camera behavior only.

Before any acceptance run, identify the completed checkpoint, artifact/revision, exact commands, environments, and expected duration, then obtain explicit permission under the [testing policy](testing-policy.md#acceptance-timing-and-user-permission). New TF08 commands should be documented only once their harness exists. Record first-attempt failures and approved retries separately, retain compact provenance/outcome evidence, and remove temporary consumers, downloads, binaries, and logs after the checkpoint.

TF08 is complete only when the mapped implementation, required routine checks, applicable approved renderer/service scenarios, and required device claims have evidence. Unresolved permission integration, capture scope, snapshot sizing, or native promise defects remain visible gates for the contracts they affect.
