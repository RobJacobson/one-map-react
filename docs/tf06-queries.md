## Contract

`MapRef` gains `queryRenderedFeatures(target, options?)`, `querySourceFeatures(sourceId, options?)`, `getClusterExpansionZoom(sourceId, clusterId)`, `getClusterLeaves(sourceId, clusterId, limit, offset)`, `getClusterChildren(sourceId, clusterId)`, `setFeatureState(identifier, state)`, `getFeatureState(identifier)`, and `removeFeatureState(identifier, key?)`. The target is a screen point, a two-corner screen rectangle (top-left, bottom-right), or `undefined` for the visible viewport. Rendered-query options are `layers` and `filter`; source-query options are `sourceLayer` and `filter`. A feature identifier names the `source`, the feature `id`, and, for vector sources, the `sourceLayer`.

Feature state is a JSON object: `null`, `undefined`, and non-finite numbers are rejected before state dispatch, including values nested in objects and arrays. `getFeatureState` resolves `{}` when no state is stored. Results preserve backend order and duplicates; an empty array is success, while an absent or malformed native payload rejects.

Types live in [contracts/query-types.ts](../packages/one-map-react/src/contracts/query-types.ts) and compose into `MapRef`, so existing `useRef<MapRef>` consumers keep working.

## Adapter mechanics

Web dispatches rendered and source queries through the wrapper map handle synchronously and normalizes the array result. Source queries require a loaded GeoJSON or vector source and a nonempty `sourceLayer` for vector queries. Rendered queries reject any requested layer absent from the loaded style; omitted and empty layer lists retain renderer semantics. A temporary renderer error listener spans each synchronous query dispatch, so an emitted error rejects instead of becoming a successful empty result. Directly thrown errors are preserved, the normal map error callback still runs, and the temporary listener is removed in `finally`. Later unrelated error events do not alter a completed query. Cluster calls go through a `getSource` handle; the shared web wrapper record carries a `callWebCluster` step so Mapbox GL's trailing callback becomes a promise while MapLibre GL's promise passes through, mirroring the `loadWebImage` split. Feature state checks the loaded source first: missing sources, unsupported families, and vector identifiers without a nonempty `sourceLayer` reject before dispatch. An absent web read rejects. Valid calls forward the identifier object and the validated mutable state copy.

mapbox-native renders point queries through `queryRenderedFeaturesAtPoint` and rect queries through `queryRenderedFeaturesInRect` with the reordered rect; the viewport passes the empty rect. Source queries and feature state dispatch on the map. Cluster methods need the `ShapeSource` ref, so the map owns a `GeoJsonSourceRegistry` provided through React context; each mounted GeoJSON source registers its ref on attach and returns owner-bound cleanup on unmount. A stale cleanup after a replacement registration leaves the newer ref in place, even when both registrations use the same ref. This cleanup guard makes no claim about renderer support for duplicate source ids. An id with no mounted GeoJSON source rejects naming the missing facade `Source`.

maplibre-native rendered queries go through the map's `queryRenderedFeatures` with the point or corner pair forwarded and the viewport omitting the target. Source queries dispatch through the registered ref: vector sources call `querySourceFeatures` (which requires `sourceLayer`), and GeoJSON sources call `getData`, whose filtered loaded-tile collection is normalized the same way. Android calls `querySourceFeatures(filter)` on its GeoJSON source; iOS calls `featuresMatchingPredicate:` on its shape source. Loaded-tile results include hidden features and may contain clipped geometries and duplicates. The earlier smoke did not independently establish this scope. Feature state and cluster methods dispatch through the same registry, which stores both GeoJSON and vector refs with their kind. Vector feature state without `sourceLayer` rejects before dispatch.

Both native adapters register GeoJSON and vector source lifetimes with their actual family. A keyed family change selects the destination family’s written-target journal while retaining the per-source operation queue. Inactive journals remain available because native replacement can retain the earlier family’s renderer state; when that family returns, its targets reset through its current handle before state operations or frame cleanup. Cleanup never dispatches inactive-family targets through the replacement family. Subsequent remounts within each family still clear written state. An identifier’s optional `sourceLayer` does not determine the source family. They serialize state operations per source and remember written identifiers, including vector source layers; state values remain in the renderer. Same-id remounts clear each remembered target after a fully rendered frame or before accepting new state operations. Frame cleanup runs even when the consumer makes no later state call, coalesces repeated callbacks, and handles sources independently. Automatic reset failures reach `onError` once for the current generation. Pending old operations reject after a lifetime changes, and replacement cleanup waits for those operations to settle. Reset failures remain visible and block further state dispatch for that lifetime; another remount or style replacement can retry cleanup. Identifiers and validated state are copied before queued dispatch so caller mutation cannot change the target or bypass validation. Committed style changes and style-load events also invalidate state operations and rearm cleanup; invalidation precedes the user style-load callback so its writes belong to the loaded style. Equivalent serialized styles do not trigger a prop-change reset. This adaptation covers facade-written state; it does not claim ownership of direct SDK writes or add a native bridge.

## Native result normalization

`featuresFromWrapper` accepts a feature array, a `FeatureCollection`, or the JSON string Android RNMapbox returns for cluster leaves and children, and rejects an absent or non-container payload. Duplicate ids and order survive normalization. JSON syntax failures retain the parse-error message and cause; valid JSON with an invalid container retains its normalization error. `featureStateFromWrapper` resolves a nullish wrapper state to `{}`.

Android GeoJSON bridges return those ids as strings, so smoke comparisons check string identity while leaving facade results untouched. This fixture choice does not extend the facade’s feature-id contract. It checks rendered point, bounds, viewport, and empty results; rendered/source filters; exclusion of a New York feature outside Seattle's loaded source tiles; finite cluster expansion; known leaf ids and pagination; and nonempty children. State must read back before each reset. The scenario checks removal of one key, preservation of another key, whole-state removal, source recreation, and style replacement.

Query execution switches its phase, source revision, and style in one React state update and runs once. A revision property first appears in rendered-query results through the stable map handle, proving that a frame contains the replacement source before source-ref queries begin. Source-query results must then carry the same revision before state checks begin. Polling reads never overlap. State removal is observed every 100 ms for up to five seconds; an operational failure ends the observation immediately. Replacement-style observation rearms before the style request, retaining synchronous load notifications. The rendered readiness query omits layer restrictions while remounted layers may be absent; the unique revision property identifies the replacement data. Source readiness is bounded. Phase cleanup cancels pending observation and ignores late query completion.
