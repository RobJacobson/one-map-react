# TF10 candidate and release gates

**Working control layout migration.** Common Control, its props, adapter field and selected facade aliases, web custom-control composition, and native corner registration/measurement and automatic SDK ornament avoidance are removed. Application screen or DOM siblings own placement, stacking, safe areas and overlap. Native live-marker hosts/portals, viewport layout, observed camera state and react-native-teleport remain. Selected SDK ornament options/defaults, legal attribution and logos, and the RNMapbox scale-position/resize refresh remain. See [layout migration guidance](revised-api-proposal.md#markers-images-popups-and-controls) and [U17 status](revised-api-implementation-plan.md#u17-remove-common-control-layout). Historical instructions and outcomes below retain their recorded artifact scope. Changed renderer layout, touches, assistive technology, Metro and native builds/installations remain unverified.

**Working geolocation UI migration.** Common GeolocateControl, its props, adapter field and selected facade aliases, and the common follow controller are removed. Web applications use raw selected WrapperGeolocateControl with upstream props and lifetime; MapSetup.locationProvider does not intercept that control. Native applications use an ordinary screen button and their chosen location integration, with application-owned request cleanup and errors. Supplied UserLocation geometry and accuracy display, GeolocationPosition, raw SDK pucks and selected follow options remain. Native viewState and locationOptions follow retain mutually exclusive camera ownership. Location services, useMapServices, MapServices, MapSetup.locationProvider and acquisition types/factories remain until U18; Source.onClick and UserLocation.onPress remain until U19. See [location migration guidance](revised-api-proposal.md#setup-and-location) and [U16 status](revised-api-implementation-plan.md#u16-remove-common-geolocation-control-and-follow-controller). Historical acquisition/follow acceptance below retains its recorded artifact scope. Changed browser geolocation, native button behavior, sensors, Metro and native builds/installations remain unverified.

**Working scale and attribution migration.** Common ScaleControl and AttributionControl, their props, adapter fields and selected facade aliases are removed. Web applications use raw WrapperScaleControl and WrapperAttributionControl. Native applications use selected SDK ornament options; SDK defaults and explicit positions remain, with no common width or units policy. Legal attribution and logos remain required. Native compass options, live-marker hosts/portals and the RNMapbox scale-position/resize workaround remain. See [ornament migration guidance](revised-api-proposal.md#markers-images-popups-and-controls) and [U15 status](revised-api-implementation-plan.md#u15-delegate-scale-and-attribution-ornaments). Historical control contracts and acceptance below retain their recorded artifacts; migrated ornaments remain unverified in renderers.

**Working navigation and fullscreen migration.** Common NavigationControl and FullscreenControl composition, props, adapter fields and selected facade aliases are removed. Web applications use raw selected WrapperNavigationControl and WrapperFullscreenControl; native applications own camera buttons in screen UI. Camera methods/getters and native SDK compass options remain. The [control migration contract](revised-api-proposal.md#markers-images-popups-and-controls) describes ownership; [U14 status](revised-api-implementation-plan.md#u14-remove-common-navigation-and-fullscreen-controls) owns verification gates. Historical control contracts and acceptance below keep their recorded artifact scope; renderer interaction and native screen button touches remain unverified.

**Working popup migration.** Common Popup composition is removed, following the [popup migration contract](revised-api-proposal.md#markers-images-popups-and-controls), in favor of direct web WrapperPopup and application-owned native Marker children or selected annotations/Callout. Common automatic dismissal, focus and maxWidth guarantees are excluded. The [U13 status](revised-api-implementation-plan.md#u13-remove-common-popup-composition) owns implementation and verification gates. Popup contracts, scenarios and acceptance results below retain their historical artifact scope; they do not verify migrated native bubble touches or provider/state retention.

**Working offline migration.** Native offline operations use the selected WrapperOfflineManager. The common OfflineService, OfflinePack types, and MapServices.offline are removed. Applications own native pack keys, metadata lookup, observers, errors, and recovery. Keep existing databases, packs, metadata, and imported backend aliases intact. Common location services remain until U18. See [offline migration](revised-api-proposal.md#offline-creation-and-existing-packs) and [U11 status](revised-api-implementation-plan.md#u11-migrate-offline-use-and-remove-the-common-manager). Live downloads, imports, cache/database operations, renderer execution, and native builds/installations are unverified for this migration. The service contracts and acceptance results below retain their historical artifact scope.

**Working capture overlay.** Working current-map capture uses selected wrapper access: RNMapbox takeSnap, MapLibre Native createStaticMapImage, or web getMap().getCanvas().toDataURL after application-selected drawing-buffer setup. MapRef.capture and Map.captureEnabled are removed. Applications own ref checks, readiness, output validation, errors, inclusion, dimensions, files, and bounded waiting. Working independent images use selected WrapperSnapshotManager and WrapperStaticMapImageManager. MapServices.staticMapImage and common capture/image-output types are removed; applications own inputs, output, errors, and waiting. Changed image routes have no renderer acceptance. See the [capture migration](revised-api-proposal.md#capture-and-advanced-ref-access) and [U10 status](revised-api-implementation-plan.md#u10-migrate-and-remove-common-map-capture). Capture guarantees, renderer observations, and execution instructions below retain their historical artifact scope.

**Working feature-state overlay.** U09 migration is implemented and audited, with routine verification recorded under the [renderer-owned lifetime contract](revised-api-proposal.md#camera-and-feature-state-guarantees); the [query record](tf06-queries.md) explains the working semantics and its separate verification status. Reset guarantees, outcomes, and instructions below apply only to their historical artifacts; renderer acceptance for the changed implementation is unverified.

**Working native camera overlay.** The [agreed camera contract](revised-api-proposal.md#camera-and-feature-state-guarantees) gives native viewState changed-target semantics, with observations driving events and readouts. U08 migration is merged as PR27; [routine verification is recorded](../records/evidence/revised-api-u08-native-camera.json). Historical rejection, release, clamping, command-overlap outcomes, and rollback-specific native probe instructions below belong to their recorded artifacts; that rollback probe is retired in the working native fixtures. These records do not verify the changed implementation; its renderer acceptance is unverified. Web controlled behavior remains delegated.

The prepared camera probe accepts `controlled-camera` with `{enabled:true, accept:false}` to reject proposals, `{enabled:true, accept:true}` to accept committed proposals, and `{enabled:false}` to release control. `{enabled:true, accept:false, clamp:true}` sets minZoom 3 while the controlled target remains zoom 2; `camera-read.clamp` confirms the committed configuration. Resetting the command without clamp or releasing control clears this minimum. `camera-command` issues a distinct common jump and `camera-read` returns target, latest event viewState/origin/counts and independent center/zoom. Actual native gesture input must demonstrate rejection, acceptance, release, bounds/zoom clamping without loops, a fresh gesture after clamping and a public command while a correction is pending. Check bearing/pitch from the latest event as well as center/zoom. Arming the fixture or passing its mocked protocol test does not pass this gate.
