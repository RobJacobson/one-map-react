# API coverage checklist

This is the sole coverage record for the thin facade. Each row covers an application contract or a group of unchanged forwarded fields. The owning code and representative tests define the route. [Upstream research notes](upstream-research.md) preserve useful versioned findings and primary-source citations; consult upstream declarations for individual API signatures and defaults.

The review checkboxes, coverage boundaries, and source/test routes below describe the **current TF contract only**. A checked row means its current route or substantiated boundary was reviewed; it establishes neither renderer acceptance nor next-release completion. An unchecked row preserves current unfinished work or an open gate, including owner exclusions. The first three cells preserve that candidate's historical routes, including method-mirror helpers and tests removed by U06 and native marker drag routes being retired by U07. They do not describe the working next-release runtime surface.

The next-release column records the agreed disposition and implementation/review owner from the [unit plan](revised-api-implementation-plan.md#work-order). Full coverage applies to the [retained next-release contract](requirements.md#purpose-and-scope), with deliberate exclusions separate from SDK limitations. getWrapperMap replaces selected method mirrors only; it cannot complete retained common conversions or cleanup guarantees. ## Maintaining this checklist

For next-release work, update the next-release disposition only after its unit is reviewed and verified; preserve current-only evidence until the contract transition is complete. A deliberate exclusion records a scope decision and migration status, never a newly checked SDK limitation. When a public API changes, find its owning row and inspect the supported peer's actual export, declaration and wrapper call. Unchanged fields stay grouped under that route. Add or split a row when conversion, lifecycle, version support, error behavior or an exception needs separate review. Preserve representative source/test links and explicitly mark unfinished work; do not add a row for each inherited host field, schema token or alias. Duplicate MapInstance/MapRef views of one operation belong to the same contract.

For a peer upgrade, compare the new exports, declarations, style schema and release notes with the [cited upstream sources](upstream-research.md) and [support matrix](../records/support-matrix.json). Review changed fields against the owning rows and add meaningful exceptions before claiming completeness. Keep useful findings and citations in the research notes; keep all coverage decisions and open work in this checklist. This manual review replaces neither tests nor release acceptance; documentation checks only validate structure and links.

Historical evidence may mention the retired JSON inventory or its checker. Those paths describe their original commits and artifacts. The [retired ledger at the last inventory commit](https://github.com/RobJacobson/one-map-react/blob/cb12433fd9f1a68ef8a8fcf5eaf65e34a0c69e39/records/api-coverage.json) remains available through Git. The [checklist migration evidence](../records/evidence/coverage-checklist-migration.json) records research preservation, coverage grouping, storage savings and routine verification; it is a checkpoint record, not another active inventory.
