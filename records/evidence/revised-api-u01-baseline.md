### Ownership couplings that constrain deletion order

- Native frame callbacks serve capture.frame and featureState.flush/reset. U09 retains capture delivery until U10 removes capture. Removing one owner does not authorize deleting the other owner's callback or selected SDK forwarding.
- UserLocation imports validatePosition from shared/location-values.ts. U18 must preserve that display validation when deleting acquisition helpers; U19 removes its separate press callback dependency.
- Native live MarkerOverlay reads observed camera, nativeLayout and overlayHostName. U17/U21 cannot delete these or Teleport solely because common controls are gone. A source-ref registry used by queries is also independent of synthetic source event registration.
- The native drag hook currently owns ordinary marker tap handling. U07 must replace that retained path and preserve child button/scroll behavior while removing drag coordination.
- Image ownership checks guard callbacks that can synchronously replace a style or unmount the map. The image replay exclusion does not permit an old load or cleanup to alter a replacement style.
- RNMapbox patch sections include event isolation, ordinary camera dispatch/reset, terrain/light conversion and source/state errors, as well as service repairs and generated-module linking. A whole patch file cannot be classified by its TF08 filename.
